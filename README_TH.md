# AI Worksheet Cleaner — Phase 1–3 (Phase 2–3 เป็นต้นแบบ)

ลบรอยปากกาแดง/น้ำเงินจากใบงานเด็ก (JPG/PNG/TIFF/BMP/PDF) โดย **รักษาเนื้อหาพิมพ์ก่อนเสมอ** — ประมวลผลในเครื่อง ไม่ใช้อินเทอร์เน็ต

## สถานะตามสเปก (ตรงไปตรงมา)
| Phase | สถานะ |
|---|---|
| 1 แอป + ตรวจจับสีแดง/น้ำเงิน + แก้ Mask + ลบแบบ Safe + Export | **ทำแล้ว ทดสอบแล้ว** |
| 2 โมเดล AI Segmentation (U-Net/MobileNetV3) | **ทำแล้ว (ต้นแบบ)** — มีสคริปต์สร้างข้อมูล/เทรน/วัดผล/ส่งออก ONNX→OpenVINO และโมเดลต้นแบบที่เทรนจาก **ข้อมูลสังเคราะห์เท่านั้น** ยังไม่เคยพิสูจน์กับใบงานจริง |
| 3 ตรวจจับดินสอ | **ทำแล้ว (ต้นแบบ แม่นยำต่ำ)** — โมเดลดินสอ + ตัวตรวจจับแบบดั้งเดิมที่ระมัดระวัง + ติดธงเมื่อดินสอทับเนื้อหาพิมพ์ ดูหัวข้อ Phase 3 |
| 4 ฟื้นฟูขั้นสูง (ข้อความทับ, ซ่อมเส้นประ, OCR) | บางส่วน: ลากเส้นตารางต่อ, QA ติดธงบริเวณทับเนื้อหาพิมพ์; **ยังไม่มี OCR** |
| 5 Intel NPU | ทำเฉพาะชั้นตรวจอุปกรณ์ + ตัวรัน OpenVINO + self-test; **ยังไม่มีโมเดลให้รัน** จึงยังไม่เคยรันบน NPU และไม่มีผล benchmark |
| 6 Production (EXE/ติดตั้ง) | สคริปต์ `build_exe.bat` มีให้ แต่ **ยังไม่ได้สร้าง/ทดสอบบน Windows** |

โมเดลที่ยังขาด: `restoration/restore_net.xml` (Phase 4)
ค่าเริ่มต้นของแอปยังเป็น **ตัวตรวจจับสีแบบคลาสสิก (CPU/OpenCV)** — โหมด AI ต้องเลือกเองในกล่อง "การตรวจจับ (AI)" และแอปแสดงอุปกรณ์ที่รันจริงเสมอ

## ติดตั้งและรัน (Windows 10/11, Python 3.11/3.12)
```bat
scripts\install.bat
scripts\run.bat            :: หรือ python main.py ไฟล์.pdf
```
สร้าง EXE: `scripts\build_exe.bat`

## วิธีใช้
1. **Open File / Open Folder** หรือลากไฟล์มาวาง (ภาพหลายหน้า TIFF และ PDF หลายหน้ารองรับ)
2. เลือกโหมด: **Safe** (ค่าเริ่มต้น ลบเฉพาะที่มั่นใจ) / Balanced / Deep Cleaning ปรับความไวสีแดง/น้ำเงินแยกกันได้
3. **Preview** แล้วสลับดู *Final Removal / Detection / Protection Mask* (สีเขียว)
4. แก้ด้วยแปรง: เพิ่มพื้นที่ลบ, คืนพื้นที่, Undo/Redo, Reset
5. **Process Current / All Pages** → ดูบันทึกด้านล่าง: เวลา, อุปกรณ์จริง, และ ⚠ บริเวณที่รอยทับเนื้อหาพิมพ์ (กู้คืนไม่แน่ชัด ต้องตรวจด้วยตา)
6. **Export…** เลือก PNG/JPG/TIFF/PDF + (ต้นฉบับ, Side-by-side, Mask, รายงาน JSON) — ไม่เขียนทับไฟล์เดิม (ถ้าชื่อซ้ำจะใส่เลข `_1`)

## หลักการป้องกันเนื้อหาพิมพ์ (Protection Engine)
Mask สุดท้าย = Detection − Protection โดย Protection รวม: ตัวพิมพ์ดำ, เส้นตาราง, เส้นประฝึกเขียน, ภาพประกอบสีหนา (ตัวการ์ตูน) และบริเวณรอบๆ (ปรับด้วย Preservation Strength)
ไม่ใช้การลบสีทั้งหน้า ไม่มี global blur/threshold/denoise

## ข้อจำกัดที่ทราบ
- ข้อมูลทดสอบเป็นใบงาน **สังเคราะห์** ยังไม่เคยลองกับใบงานสแกนจริง ควรทดลองและปรับความไว
- หมึกทึบทับตัวพิมพ์: ข้อมูลใต้หมึกกู้คืนไม่ได้ ระบบไม่สร้างเนื้อหาใหม่ และติดธงให้ตรวจ
- ปากกาที่ทับภาพสีสดขนาดใหญ่ไม่ถูกตรวจอัตโนมัติ (เพื่อไม่ทำลายภาพ) ใช้แปรงเอง
- ตรวจแนวหน้ากระดาษจาก EXIF เท่านั้น (ไม่มีการหมุนอัตโนมัติด้วย OCR)
- UI ภาษาไทยอย่างเดียว (ยังไม่มีสลับอังกฤษ) · Batch ทำได้เปิดทีละไฟล์ (ยังไม่มีคิว/พักต่อ)
- PDF: หน้าที่ประมวลผลกลายเป็นภาพ; Text Layer ที่เก็บคืนเป็น Latin-1 เท่านั้น (ไทยค้นหาไม่ได้)

# Phase 2: AI Ink Segmentation (ต้นแบบ)

## ที่มีให้
| ไฟล์ | หน้าที่ |
|---|---|
| `training/synthetic_data.py` | สร้างใบงานสังเคราะห์ + ลายมือจำลอง (แดง/น้ำเงิน/อื่นๆ) พร้อม label ระดับพิกเซลและภาพเป้าหมายสะอาดที่จับคู่กัน |
| `training/real_pairs.py` | นำภาพจริงที่เป็นคู่ `dirty/` + `clean/` มาสร้าง manifest พร้อม label อัตโนมัติ (ต้องตรวจทานก่อนเชื่อถือ) |
| `training/dataset.py`, `train.py` | Dataset (แบ่งชุดตาม **ใบงานต้นฉบับ** ไม่แบ่งตามแพตช์), เทรน U-Net + MobileNetV3-Small, `--resume`, `--device auto/cpu/cuda/xpu` |
| `training/evaluate.py` | Precision/Recall/F1/IoU ต่อคลาส, PSNR/SSIM, เทียบกับตัวตรวจจับสี Phase 1 บนชุดทดสอบเดียวกัน |
| `training/export_onnx.py` | Checkpoint → ONNX → OpenVINO IR (FP16) + ตรวจความตรงกับ PyTorch |
| `ai/ink_detector.py`, `ai/tiling.py` | รันโมเดลผ่าน OpenVINO แบบ tile, เลือก NPU > GPU > CPU, **รายงานอุปกรณ์ที่คอมไพล์ได้จริง** และสำรองเมื่อคอมไพล์ไม่สำเร็จ |

AI ใช้ในแอปได้ที่ "การตรวจจับ (AI)": *AI + สี* หรือ *AI อย่างเดียว* — ผลจาก AI **ยังถูกหัก Protection Mask เสมอ** (ลบเนื้อหาพิมพ์ไม่ได้อัตโนมัติ) และบริเวณที่ AI "ไม่มั่นใจ" จะถูกติดธงให้ตรวจด้วยตา ไม่ถูกลบ

## เทรนด้วยตัวเอง (แนะนำให้ทำบนเครื่องที่มี GPU หรือเทรนนานขึ้นบน CPU)
```bat
pip install torch torchvision onnx
python -m training.synthetic_data --out data\syn --n 300 --versions 3 --seed 1
python -m training.train --data data\syn\manifest.json --out runs\r1 --epochs 40 --batch 16 --crop 256 --pretrained
python -m training.evaluate --data data\syn\manifest.json --ckpt runs\r1\best.pt --out runs\r1\eval.json
python -m training.export_onnx --ckpt runs\r1\best.pt --out models\ink_segmentation
```
ข้อมูลจริง: วางภาพเป็น `raw\dirty\ชื่อ.png` กับ `raw\clean\ชื่อ.png` แล้ว `python -c "from training.real_pairs import build_manifest as b; b('raw','data/real')"` จากนั้นเทรนด้วย manifest นั้น (หรือรวมกับข้อมูลสังเคราะห์) — **นี่คือสิ่งที่จำเป็นที่สุดเพื่อให้ผลจริงน่าเชื่อถือ**

## ผลที่วัดได้จริง (โมเดลต้นแบบที่แนบมา)
เงื่อนไข: เทรน 14 epoch (882 steps, CPU 1 คอร์, ~15 นาที) บนใบงานสังเคราะห์ 42 ใบ (84 ภาพ); ทดสอบกับใบงาน **9 ใบที่ไม่เคยใช้เทรน** (18 ภาพ, 100 DPI) — ดู `models/ink_segmentation/*.json`

| ตัวชี้วัด (ชุดทดสอบสังเคราะห์) | AI ต้นแบบ | ตัวตรวจจับสี Phase 1 |
|---|---|---|
| ลายมือ (ทุกชนิดรวมกัน) Precision / Recall / F1 / IoU | 0.88 / 0.90 / 0.89 / 0.80 | 0.64 / 0.48 / 0.53 / 0.38 |
| red_ink IoU / blue_ink IoU / other_handwriting IoU | 0.76 / 0.79 / 0.73 | — |
| printed IoU / background IoU | 0.86 / 0.99 | — |
| PSNR บริเวณรอยปากกา (8 ภาพ, หลังฟื้นฟู) | 17.8 dB | 13.0 dB (ไม่ประมวลผล: 10.7 dB) |
| PSNR / SSIM ทั้งหน้า (8 ภาพ) | 33.4 dB / 0.995 | 30.6 dB / 0.992 |

**ต้องอ่านอย่างระวัง:**
- ตัวเลขทั้งหมดมาจาก **ข้อมูลสังเคราะห์ที่สร้างด้วยตัวสร้างเดียวกับที่ใช้เทรน** ไม่ใช่ใบงานจริง จึงมีโอกาสสูงกว่าผลจริงมาก ห้ามใช้เป็นตัวเลขความแม่นยำของระบบ
- ตัวตรวจจับสี Phase 1 ในตารางนี้ต่ำกว่าที่เคยวัดกับใบงานชุดอื่น เพราะข้อมูล Phase 2 มีลายมือบางเส้น สีจาง และ "other_handwriting" (สีดำ/เทา) ซึ่งตัวตรวจจับสีไม่ได้ออกแบบไว้
- **ไม่ได้วัด OCR text preservation rate** (ไม่มี OCR engine) และ **ไม่ได้ทำ INT8 quantization** (สเปกให้ทำหลังวัดผลกระทบเท่านั้น; ใช้ FP16)
- ความเร็ว: โมเดลต้นแบบรัน ~0.4 วินาที/หน้า A4 ที่ 200 DPI บน CPU 1 คอร์ (เครื่องทดสอบ) — **ไม่มีตัวเลข NPU** เพราะยังไม่เคยรันบน Intel NPU จริง
- ยังไม่มีข้อมูลภาษาไทยในชุดสังเคราะห์ (ไม่มีฟอนต์ไทยใน generator) และเทรนจาก weight เริ่มต้นแบบสุ่ม (ไม่ใช่ ImageNet pretrained เพราะเครื่องทดสอบดาวน์โหลดไม่ได้; ใช้ `--pretrained` บนเครื่องที่มีอินเทอร์เน็ตตอนเทรน)

## ทดสอบ
`pytest -v` → **50 passed** (ดู `TEST_RESULTS.txt`) เพิ่มจาก Phase 1: ความถูกต้องของข้อมูลสังเคราะห์และ label, แบ่งชุดตามใบงานไม่รั่ว, โครงสร้างโมเดล/ฟังก์ชันสูญเสีย/ overfit batch เดียว, เทรนจริงแบบสั้น, metric (confusion/PSNR/SSIM), ONNX→OpenVINO ตรงกับ PyTorch, tiling, อุปกรณ์รายงานจริง (ขอ NPU แต่ไม่มี → สำรองเป็น CPU และบอกตรงๆ), AI ไม่ลบเนื้อหาที่ป้องกันไว้
(เทสต์ Phase 2 ต้องติดตั้ง torch; ถ้าไม่มีจะถูกข้าม)

# Phase 3: ตรวจจับดินสอ (ต้นแบบ — แม่นยำต่ำ)

## ที่เพิ่มมา
| ส่วน | รายละเอียด |
|---|---|
| ข้อมูลสังเคราะห์ดินสอ | `python -m training.synthetic_data --pencil` — เส้นแกรไฟต์เม็ดหยาบ (grain), แรงกดไม่สม่ำเสมอ, วงกลม/ติ๊ก/ขีดฆ่า/ลายเส้น/ตัวเลข + **ตัวพิมพ์สีเทาเป็น hard negative** (ข้อความเทา, ตารางเทา, เส้นประเทา, พื้นเทา) ที่ต้องไม่ถูกลบ |
| โมเดลดินสอ | `models/pencil_segmentation/pencil_unet.xml` (U-Net/MobileNetV3, fine-tune จากโมเดลหมึก, FP16) + `training/evaluate_pencil.py` วัดผลผ่านเส้นทาง runtime จริง |
| ตัวตรวจจับแบบดั้งเดิม | `ai/pencil_detector.py::classical_pencil_mask` — ใช้เมื่อไม่ได้เลือกโหมด AI/ไม่มีโมเดล: เทียบความเข้มกับกระดาษรอบข้าง, ตัดเงาขอบตัวพิมพ์, กรองข้อความเทา/บล็อกทึบ/เส้นตาราง |
| ธงตรวจด้วยตา | ดินสอที่ **ติดกับ/ทับตัวพิมพ์** จะไม่ถูกลบอัตโนมัติ แต่ถูกติดธง "ควรตรวจด้วยตา" ใน QA |
| เพิ่มเติมใน Protection | แยก "เส้นตารางพิมพ์ (บาง คม)" ออกจาก "เส้นขีดหนาด้วยมือ" และป้องกันเส้นตารางสีเทาจางด้วย |

เปิดใช้: ติ๊ก **"ดินสอ (ทดลอง)"** (ถ้าเลือก AI + มีโมเดล จะใช้โมเดล ไม่เช่นนั้นใช้วิธีดั้งเดิม) — มีตัวเลือก `pencil_override_print` ในโค้ด (ปิดไว้) ให้ AI ที่มั่นใจมากเขียนทับการป้องกันตัวพิมพ์เข้ม

## ผลที่วัดได้จริง (ใบงานสังเคราะห์ 6 ภาพที่ไม่เคยใช้เทรน, 100 DPI, โหมด Safe / Balanced)
| ตัวชี้วัด | AI (Safe) | AI (Balanced) | ดั้งเดิม (Safe) | ดั้งเดิม (Balanced) |
|---|---|---|---|---|
| Precision / Recall | 0.42 / 0.46 | 0.37 / 0.49 | 0.37 / 0.23 | 0.32 / 0.23 |
| F1 / IoU | **0.43 / 0.29** | 0.41 / 0.27 | 0.28 / 0.16 | 0.27 / 0.16 |
| พิกเซลผิดบนหน้าสะอาด (ต่อหน้า) | 93 | 186 | 33 | 86 |
| หน้าสะอาดที่มีพิกเซลผิดอย่างน้อย 1 จุด | 50% | 67% | 17% | 17% |
| ตัวพิมพ์ที่หลุดเข้า Mask ลบ (พิกเซล/หน้า) | 52 | 108 | — | — |
| PSNR บริเวณรอยดินสอหลังฟื้นฟู (ไม่ประมวลผล 21.7 dB) | 24.8 dB | 25.1 dB | 23.0 dB | 22.8 dB |

**สรุปตรงๆ: ดินสอยังทำได้ไม่ดี** — ตรวจพบครึ่งหนึ่งแต่ผิดพลาดมาก ห้ามเชื่อถือโดยไม่ตรวจผล โหมด Safe ผิดพลาดน้อยกว่าและแนะนำกว่า
- **~45% ของพิกเซลดินสอ (ในข้อมูลทดสอบ) อยู่ในบริเวณที่ Protection ป้องกันไว้** (ดินสอทับ/ติดตัวพิมพ์ และเส้นบางตรงที่แยกจากเส้นตารางไม่ได้) → จะ **ไม่ถูกลบอัตโนมัติ** ต้องใช้แปรงเอง สัดส่วนนี้ขึ้นกับตัวสร้างข้อมูล (ตั้งให้ 50% ของเส้นเริ่มบนตัวพิมพ์)
- **เส้นดินสอบางที่ลากตรงเหมือนไม้บรรทัด แยกจากเส้นตารางพิมพ์ไม่ได้** จึงถูกป้องกันไว้ (เลือกปลอดภัยไว้ก่อน)
- ตัวเลขนี้มาจากข้อมูลสังเคราะห์ที่สร้างด้วยตัวสร้างเดียวกับที่เทรน และวัดเพียง 6 ภาพ จึงสูงกว่าผลจริงได้ และมีความไม่แน่นอนมาก

# ข้อมูลจริง: ชุดที่ 1 (PDF คู่ 24 หน้า, หน้า 5–28 ของใบงานภาพ)

## วิธีสร้างป้ายกำกับจาก PDF คู่ (`training/real_pdf_pairs.py`)
`render → จัดภาพให้ซ้อนกัน (ORB+RANSAC แล้วปรับด้วย ECC) → หาหมึกที่ "เพิ่ม" เข้ามา (เข้มกว่าทุกพิกเซลของฉบับสะอาดในระยะ 2px) → แยกชนิดตามสี: แดง / น้ำเงิน / ดินสอ(สีเทา)`
- ป้ายนี้เป็น **ป้ายแบบประมาณ (weak labels)** — ลายมือที่ทับเส้นพิมพ์สีดำสนิทแยกด้วยการลบภาพไม่ได้ จึงตกหล่น และปากกาดำจะถูกนับเป็น "ดินสอ"
- ตรวจด้วยตาจากภาพซ้อนแล้ว (หน้า 5 และ 13): เส้นปากกาแดงและเส้นดินสอตรงตำแหน่งจริง
- ทั้ง 24 หน้าจัดภาพได้ (ความตรงของเส้นพิมพ์ ≥ 0.99) · **ไม่พบปากกาน้ำเงินในชุดนี้** (≈ 0 พิกเซล) จึงยังวัดน้ำเงินกับข้อมูลจริงไม่ได้
- ข้อควรระวัง: ภาพวาดเดียวกันปรากฏซ้ำหลายหน้า/หลายชุด การแบ่งชุดตามหน้าจึงอาจทำให้ผลทดสอบดูดีเกินจริง (รั่วทางอ้อม) — ตอนรวมทั้ง 6 ชุดจะแบ่งตามภาพวาดแทน

## ผลวัดโมเดลที่มีอยู่กับใบงานจริง (ทั้ง 24 หน้า — โมเดล/ตัวตรวจจับไม่เคยเห็นข้อมูลนี้)
ความละเอียด 200 DPI · "ยอมคลาดเคลื่อน 2px" เพราะการจัดภาพสองสแกนไม่เป๊ะและ Mask ลบถูกขยายขอบโดยตั้งใจ

| วิธี | เทียบกับ | Recall | Precision | Precision (ยอม 2px) |
|---|---|---|---|---|
| ปากกาแดง: ตัวตรวจจับสี Safe (ค่าเริ่มต้น) | ปากกาแดง/น้ำเงิน 39,582 px | **0.00** | — | — |
| ปากกาแดง: ตัวตรวจจับสี Balanced | เหมือนกัน | 0.25 | 0.40 | 0.89 |
| ปากกาแดง: โมเดล AI หมึก (Balanced) | เหมือนกัน | 0.27 | 0.05 | 0.09 |

- **โมเดล AI ที่เทรนจากข้อมูลสังเคราะห์ใช้กับใบงานจริงได้ไม่ดี** — ดินสอ F1 0.31 เทียบกับตัวตรวจจับดั้งเดิม 0.47, ปากกาแดง precision 0.05–0.09 ผลสังเคราะห์ก่อนหน้า (F1 0.89 / 0.41) **จึงไม่สะท้อนของจริง** นี่คือเหตุผลที่ต้องใช้ข้อมูลจริงเทรน
- **ตัวตรวจจับสีค่าเริ่มต้นพลาดปากกาแดงจางของชุดนี้เกือบหมด** แต่ปรับความไวได้ (หน้าที่มีปากกาแดง 8 หน้า): ความไว 0.75 + Balanced → recall 0.65, precision(2px) 0.84; ความไว 0.75 + Deep → recall 0.85, precision(2px) 0.80; ความไว 0.95 → recall 0.92–0.94 แต่ precision(2px) ลดเหลือ 0.63–0.69
